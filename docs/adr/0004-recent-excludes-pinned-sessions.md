# 最近区只收未置顶的会话，与置顶区互斥

「最近」区按最近更新时间收拢未置顶、未归档的普通会话。临时的新会话占位行和子智能体会话不计入最近区。两个分组同时显示时，同一会话不会在两处重复出现。即使用户在设置中隐藏了「置顶」区，已置顶会话也不会转入「最近」区。

后续新增的「从最近隐藏」是最近区的额外排除条件，不改变上述置顶与归档边界。新活动或「恢复」解除隐藏限制后，会话仍须满足未置顶、未归档等条件才会回到最近区，见 [ADR 0007](./0007-hide-from-recent-is-local-and-activity-scoped.md)。

这是唯一被认真权衡过的方案。另一种做法是让最近区成为「全部会话按更新时间排序」的视图，置顶会话也照常出现在其中。否决的原因是，两个区上下相邻，同一行在两处重复出现会让人以为列表出了问题；置顶区本身已经承担了「这些会话最近有动静」的提示职责，重复显示不带来额外信息。

代价是「最近」只覆盖一部分会话。刚聊过但已置顶的会话会按更新时间排在置顶区靠前的位置；如果隐藏了置顶区，仍可在所属工作区的列表中找到它。参见 [ADR 0001](./0001-pinned-sessions-remain-in-workspace-lists.md)。
