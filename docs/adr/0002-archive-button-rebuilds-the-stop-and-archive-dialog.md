# 置顶区的归档按钮自行复刻「停止并归档」确认框

置顶区的每一行都提供归档按钮，但它不像工作区列表那样把确认交给宿主：宿主那个「停止并归档」对话框由 `ui-workspace` 包内部的请求 store 驱动，插件调用 `ctx.uiWorkspace.archiveSession()` 无法把请求放进去，宿主也只在它自己的行按钮被按下时才会写这个 store。因此插件先做一次普通归档；只有 Host 以 `workspace/session-active` 拒绝、并在 details 里列出仍在运行的工作时，插件才在自己渲染的确认框里列出这些工作，用户确认后再带 `stopActivity: true` 重试。

另一种做法是直接带 `stopActivity: true` 归档，或干脆只做普通归档、被拒时静默失败——前者会在用户不知情时停掉正在运行的回合和后台任务，后者让按钮在会话忙碌时看起来失灵。复刻对话框的代价是宿主改版时这段 UI 需要跟着改，但它换来的是与侧栏完全一致的语义：静止的会话一次点击就归档，忙碌的会话必须显式确认。
