# 置顶区和最近区的行内归档按钮自行复刻「停止并归档」确认框

置顶区和最近区的每一行都提供归档按钮。宿主的「停止并归档」对话框由 `ui-workspace` 包内部的请求 store 驱动，插件直接调用 `ctx.uiWorkspace.archiveSession()` 无法把确认请求放进去。因此插件的行内按钮先做一次普通归档；只有宿主以 `workspace/session-active` 拒绝、并在详情里列出仍在运行的工作时，插件才在自己的确认框里列出这些工作，用户确认后再带 `stopActivity: true` 重试。

另一种做法是直接带 `stopActivity: true` 归档，或干脆只做普通归档、被拒时静默失败——前者会在用户不知情时停掉正在运行的回合和后台任务，后者让按钮在会话忙碌时看起来失灵。复刻对话框的代价是宿主改版时这段 UI 需要跟着改，但它换来的是与侧栏完全一致的语义：静止的会话一次点击就归档，忙碌的会话必须显式确认。

两个分组接入 DSH 的会话菜单后，从菜单选择「归档」会走宿主注册的归档操作及其确认流程。插件仍保留行内归档按钮，所以上述确认框继续服务于直接点击行内按钮的路径。
