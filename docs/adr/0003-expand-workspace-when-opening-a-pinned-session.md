# 打开置顶会话时通过点击工作区行来展开它

点击置顶区的一行时，插件先展开该会话所属的工作区，再打开会话；在「工作区树」分组下，如果该工作区的某个祖先处于收起状态，也把沿途的祖先依次展开。展开只影响折叠状态，置顶区自己那行的选中高亮（`dshUS-current`）和侧栏原生的选中行都仍由宿主的主视图引用决定，插件不另立一套。

展开能力没有可供插件调用的服务。宿主的展开状态属于 `ui-workspace` 包内部的浏览器本地视图 store（`dsh.workspace.view.v5`，`groupExpansion` 按工作区 id 记录 `true`/`false`），`ctx.uiWorkspace` 不暴露 `setGroupExpanded`；而这份 store 只在创建时读一次 `localStorage`，此后只往写，不监听 `storage` 事件。因此插件直接改存储既不会让界面响应，也会在下一次宿主写入时被覆盖。插件于是改为驱动宿主自己的展开开关：工作区行带着 `data-row-key="workspace:<id>"` 和 `aria-expanded`，点击处理就是宿主表头用的那一个，点击一行既展开分组，也照常把选择写回那份本地存储。

展开时遵循宿主自己的规则：目标工作区那一行始终点开；祖先只在「下一级的行根本不在 DOM 里」时才点——这正是工作区树里父级收起的情形，而平铺分组总是渲染每一个工作区行，所以不会顺带展开无关的父目录。React 对离散点击的更新会在 `dispatchEvent` 返回前提交，因此外层点开后，子行通常已在同一次调用里可查；即便如此仍保留几帧的有限重试，以应对宿主改版后更晚的提交，并且每个工作区在一次调用中最多只点一次，避免「点开又被点收」。

代价是这段逻辑依赖宿主的 DOM 约定：`data-slot="sidebar.workspaces"`、`data-row-key` 的前缀与 `aria-expanded` 三处。它们不是公开 API，但 `data-row-key` 早已被本插件用来对齐行宽（`alignToNativeRows`），宿主自己的行动画也依赖同一批属性，所以这不是新引入的脆弱点；换来的是与用户亲手点一次表头完全等价的行为，包括宿主原本的展开持久化。

被否决的做法有两个。其一，直接写 `localStorage` 并伪造 `storage` 事件：store 创建后不再监听存储，伪造事件只会让它保持原值，界面不会变，记录还会在下次宿主写入时被冲掉。其二，把置顶行改成「先跳到工作区、再让用户自己点会话」：那会让一次点击变成两次，也破坏了「点一下就在主区看到该会话」的既有语义。
