# 插件的设置保存在浏览器本地存储

插件的设置弹窗有三项偏好：「显示置顶」「显示最近」和「展开工作区中的原会话」，默认都开启。它们保存在 `localStorage` 的 `dsh-up-session/preferences.v1` 键下，组成一个 JSON 对象；缺失、损坏、字段值无效或读不到存储时，相应偏好回落到默认值。读取只发生在组件挂载时，点击开关后设置立即生效并写入存储，没有保存按钮。关闭「显示置顶」不会使已置顶会话转入最近区。

两个分组的标题栏与插件详情页共用同一个设置弹窗。详情页保留「打开设置」入口，因此即使同时隐藏两个分组，用户也能重新开启它们。

选择本地存储而不是宿主的设置文档，原因有三点。插件是纯 Client 侧边栏装饰，Host 侧只是一个空 `apply()`；要把偏好放进 Host 设置，需要给插件增加 Schemastery 配置、确认该条目的设置命名空间会被服务端投影，并处理在线改写配置时的插件重载语义。这些偏好只影响本插件的列表显示和点击行为，不参与任何 Host 能力，跨浏览器同步也不是需求。最后，同一个 profile 里其他第三方插件也把浏览器本地偏好放在 `localStorage`，这样本插件与它们的做法一致。

代价是设置按浏览器（来源）保存：换浏览器、换来源端口或清空站点数据都会回到默认开启；它也不会同步到其他设备。键名带 `v1`，将来改变记录形状时可以迁移或换键，而不是误读旧值。更新单项偏好时，组件先合并当前的三项设置，再由 `writePreferences` 整体写入记录；以后新增字段也需要保持这种合并方式，避免切换一个开关时丢掉其他设置。
