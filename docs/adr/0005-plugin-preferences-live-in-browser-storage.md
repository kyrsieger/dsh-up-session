# 插件的设置保存在浏览器本地存储

插件的设置弹窗有四项偏好：「显示置顶」「显示最近」「展开工作区中的原会话」和「最近区默认展示的会话数」。两个显示开关与展开行为默认开启，显示数量默认 5 条。它们保存在 `localStorage` 的 `dsh-up-session/preferences.v1` 键下，组成一个 JSON 对象；缺失、损坏、字段值无效或读不到存储时，相应偏好回落到默认值。布尔值与数字分别校验：显示数量只接受数字，取整后限制在 1–50，其他值回落到 5。读取只发生在组件挂载时，点击开关后设置立即生效并写入存储；数量只在按回车、离开输入框或点击右侧上下按键时生效，键入本身不会立即改变列表，确认时把越界或空白的草稿校正为有效值，上下按键每次增减 1。没有保存按钮。关闭「显示置顶」不会使已置顶会话转入最近区。

两个分组的标题栏与插件详情页共用同一个设置弹窗。详情页保留「打开设置」入口，因此即使同时隐藏两个分组，用户也能重新开启它们。

后续在同一弹窗加入「已隐藏的会话」及「恢复」操作，它们管理的是独立的会话隐藏记录，不是第五项偏好，也不并入 `preferences.v1`。记录的存储边界与失效规则见 [ADR 0007](./0007-hide-from-recent-is-local-and-activity-scoped.md)。

此后新增的第五项偏好「最近区时间过滤」沿用同一存储方案，字段为 `recentTimeFilterDays`。它只接受 0–99 的整数，默认 7；0 表示不进行时间过滤。缺失、损坏或无效值回落到 7，不取整或限制到边界。输入确认时无效草稿恢复之前的有效值，更新其他偏好时也保留该字段。前述四项设置及其合并方式是最初的决策背景，当前写入会合并全部五项偏好；具体过滤与刷新规则见[功能设计](../recent-time-filter.md)。

选择本地存储而不是宿主的设置文档，原因有三点。插件是纯 Client 侧边栏装饰，Host 侧只是一个空 `apply()`；要把偏好放进 Host 设置，需要给插件增加 Schemastery 配置、确认该条目的设置命名空间会被服务端投影，并处理在线改写配置时的插件重载语义。这些偏好只影响本插件的列表显示和点击行为，不参与任何 Host 能力，跨浏览器同步也不是需求。最后，同一个 profile 里其他第三方插件也把浏览器本地偏好放在 `localStorage`，这样本插件与它们的做法一致。

代价是设置按浏览器（来源）保存：换浏览器、换来源端口或清空站点数据都会回到默认值；它也不会同步到其他设备。键名带 `v1`，将来改变记录形状时可以迁移或换键，而不是误读旧值。更新单项偏好时，组件先合并当前的四项设置，再由 `writePreferences` 整体写入记录；以后新增字段也需要保持这种合并方式，避免切换一个开关时丢掉其他设置。最近区只把这一项数量当作静止时显示的条数；「展开更多」每次固定增加 5 条，不随这个设置变化，因此调大默认展示数量不会让每次展开的跨度一起变大。
