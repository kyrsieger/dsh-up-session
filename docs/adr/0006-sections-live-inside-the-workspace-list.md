# 置顶区和最近区并入工作区列表

侧边栏的「置顶」和「最近」不再作为「工作区」区上方的两个并列区，而是挂到「工作区」列表的滚动容器顶部，成为该列表的前两个分组。

宿主的 `sidebar.workspaces` 是一个 `kind: single` 的槽位，`ui-workspace` 包只声明了会话菜单、行内按钮和目录选择流程等子槽位，没有给额外的分组留注册点。因此插件只能操作 DOM：把宿主节点插进工作区列表本身，而不是插在槽位锚点旁边。

滚动容器没有稳定的类名可依赖（宿主使用带哈希的 CSS Module 类名）。插件改为从 `[data-slot="sidebar.workspaces"]` 内的 `[role="tree"]` 出发，向上找第一个 `overflow-y` 为 `auto` 或 `scroll` 的祖先：分组视图和平铺视图里树自己滚动，搜索视图里结果树嵌在同一个滚动容器内，两种情况都能落到位。搜索时列表被结果接管，两个区临时隐藏，避免搜索结果上方出现与搜索无关的置顶和最近行。

这样做让两个区随工作区列表一起滚动，不再固定占掉侧边栏上半部分，读起来也是「工作区」标题下的两个分组。代价是宿主节点落在 React 管理的子树里：`ui-workspace` 在切换分组、进入搜索等时机可能重建这棵子树，插件因此保留 `MutationObserver`，在每次 DOM 变化后把节点移回列表首位；同时依赖 `data-slot`、`role="tree"` 和 `overflow-y` 三个宿主约定，宿主改版时这段挂载逻辑会先受影响。

被否决的做法是继续把两个区作为「工作区」槽位的兄弟节点、只用样式贴近列表：视觉上仍然是并列的三个区，也不会随列表滚动。另一个被否决的做法是直接依赖宿主的哈希类名定位滚动容器，那会在宿主每次构建后失效。
