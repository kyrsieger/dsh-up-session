# 最近区时间过滤

状态：已实现。

## 目的

最近区跨工作区汇总会话，长期没有更新的会话会使列表难以管理。增加时间过滤偏好，限制最近区收录范围；被过滤的会话仍保留在原工作区中，不改变其置顶、归档或从最近隐藏的记录。

## 设置与输入

- 在现有设置弹窗中增加最近区时间过滤，默认值为 7 天。
- 仅接受 0–99 的整数；0 表示不进行时间过滤。
- 输入时仅修改草稿，按回车、离开输入框或点击上下按钮时确认并保存；上下按钮每次增减 1，不超出范围。
- 小数、负数、超过 99、非数字或空白均不保存，确认时恢复之前的有效值，不自动取整或调整到边界值。
- 沿用现有偏好的浏览器本地存储方式；已有用户缺少此设置时采用默认值 7。

## 过滤规则

- 以会话最近更新时间为依据，与最近区排序及 DSH 原生相对时间的时间依据一致；单纯打开会话不延长其收录期限。
- 一天为连续 24 小时，经过的完整天数向下取整，不按自然日或本地零点划分。
- 设置为 N 天且 N 大于 0 时，达到 N 天即不再收录。例如，设置为 7 天时，距离最近更新达到 168 小时的会话被过滤，恰好显示“7 天”的会话也不保留。
- DSH 将较长时间改用月等单位显示后，仍按实际经过的天数过滤。
- 时间条件与未置顶、未归档、未从最近隐藏等现有条件同时成立，才具备最近区收录资格。
- 运行中、等待回应或当前打开的会话均不豁免时间过滤。
- “展开更多”只展示通过过滤的会话；“恢复已隐藏的会话”不绕过时间条件。

## 刷新方式

只利用原生会话已有的更新机制。插件已订阅整份会话列表和整份会话状态表；相关更新触发重新计算时，使用当下时间检查全部候选会话的收录资格，而不只检查发生变化的会话。确认修改过滤设置时也立即按新值重新计算。

例如，已有 A、B、C 三条会话，A 一直空闲且没有新对话。当用户点击 B 或 C、触发原生共享会话列表更新时，也重新检查 A；若 A 已达到设定期限，就将其排除在最近区之外，不需要等待 A 自己发生变化。

不新增周期或零点定时任务，不增加页面恢复可见、窗口获得焦点等补刷新监听。只有整个页面没有触发相关更新时，会话达到期限后才可能暂时保留，等现有更新机制下一次触发计算时再移出；单条会话保持空闲不妨碍其在其他会话触发更新时被重新检查。

DSH 原生侧边栏统一订阅会话列表和状态表，并在列表渲染时读取当前时间，再将状态和当前时间传给各行。单条会话行没有自己的分钟计时器；任意会话数据变化或切换当前会话等操作，都可能使其他空闲会话的相对时间一起更新。

选择这一方式，是为了沿用原生刷新行为并保持插件轻量，同时接受完全静止时不会立即移除刚达到期限的会话。
